# 免费方案：用「当前可达的免费域名」上线

## 先说清楚「免费」换来了什么、放弃了什么

- **换来**：零成本，今天就能在手机上打开并添加到主屏——不用买域名、不用备案、不用服务器。
- **放弃**：不在自己的域名上；而且是**共享域名，随时可能进名单**（现在这个 Vercel 站点就是前例，`*.vercel.app` 已上名单）。
- **但你这个 App 有个特殊好处**：装到主屏后 Service Worker 会把整个 App 缓存下来，**离线永久可用**。所以只要成功打开过一次，域名以后被封也不影响你每天背；只有「更新版本」那一次需要连得上。

结论：免费方案完全够用，只是别把它当"永久入口"。

## 我实测过的可达性（2026-09-18，本机网络，跑了两轮）

判断标准是 **443 是否真能连上**——污染答案是会轮换的（同一个名字，十分钟前返回 Meta，再之前返回 Dropbox，现在返回 DigitalOcean），所以按「IP 属于谁」判断会误判。

| 域名 | 443 | 说明 |
| --- | --- | --- |
| `*.vercel.app` | **不通** | 已在名单上（当前站点就是这种情况） |
| `*.workers.dev` | **不通** | 同样在名单上 |
| `*.pages.dev`（Cloudflare Pages） | 通 | **推荐**：免费、Git 推送即部署 |
| `*.edgeone.app`（腾讯云 EdgeOne Pages） | 通 | **国内节点，速度最好，需实名** |
| `*.netlify.app` | 通 | 可用 |
| `*.github.io` | 通 | 可用，但项目页是子路径（见 C） |
| `*.web.app`（Firebase Hosting） | 通 | 可用 |
| `*.deno.dev`、`*.onrender.com`、`*.surge.sh` | 通 | 可用 |

这只代表**现在**。名单会变，所以真正的策略是：代码与构建完全一样，随时能换一个入口。

## 三条免费路线

### A. Cloudflare Pages（推荐）

1. 注册 Cloudflare（邮箱即可，免费，不需要实名）
2. 控制台 → Workers & Pages → Create → Pages → Connect to Git → 选 `Jane-81z/Guoxue`
3. 构建配置：Framework preset `Vite`、Build command `npm run build`、Output directory `dist`
4. Deploy，拿到 `guoxue.pages.dev` 这类地址——实测这条域名当前可达，手机上直接打开 → 添加到主屏

以后每次 `git push`，Cloudflare 自动重新构建部署。

### B. 腾讯云 EdgeOne Pages（国内速度最好）

同样在腾讯云控制台连这个 GitHub 仓库，构建命令与输出目录相同。默认域名 `*.edgeone.app` 当前可达，走国内节点；腾讯云账号需要实名（免费）。

### C. GitHub Pages（不用新账号，但项目页在子路径）

代码已经支持子路径托管，构建时加一个环境变量即可：

```bash
# 仓库名是 Guoxue，所以子路径是 /Guoxue/
VITE_BASE=/Guoxue/ npm run build
```

然后把 `dist/` 推到 `gh-pages` 分支（或在 Settings → Pages 里配置）。因为 `base`、清单的 `start_url`/`scope`、Service Worker 的回落路径、以及前端路由的 `basename` 都跟着这个变量走，子路径下刷新与安装都正常。

## 部署后照例验一遍

```bash
# 第三个参数传 none 表示不使用代理直连
node scripts/dev/verify-deploy.mjs https://你的免费域名 none
```

它会检查：首页、`/review` 子路由回落、`manifest.webmanifest`、`sw.js` 缓存头、三张图标、线上构建产物是否与本地一致，并用无头 Chrome 真加载一次确认渲染与零报错。

## 与层级 1 的关系

两者不冲突，而且**代码、构建、验证流程完全一样**：

- 现在：免费域名先上线，手机装到主屏，立刻能用
- 以后想要"永久入口"：按 `deploy/上线清单.md` 买域名 + 备案，再把同一个 `dist` 部署上去
- 届时免费域名留着当备用入口
